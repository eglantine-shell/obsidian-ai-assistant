# Source Discovery

首轮建库不要先问“你有哪些知识库文件”，而要问：**过去的你在哪些地方留下过可以恢复的数字痕迹？**

目标不是穷尽人生，而是找到最低成本、最高信息量的历史来源，为第一轮回填建立足够的时间纵深。

## 1. 先盘点，不先设计复杂目录

优先了解用户已经有什么，而不是要求用户先改变存档习惯。

可以从这些来源里选择实际存在的部分：

- 书影音 / 游戏 / 音乐平台历史；
- 社交媒体、博客、论坛、公众号等公开或可导出的旧内容；
- 浏览器收藏、稍后读、阅读器记录；
- 本地 Documents / Downloads / Desktop / 项目文件夹；
- iCloud、Google Drive、OneDrive、Dropbox 等云盘；
- Word、PPT、Excel、PDF、Keynote、Pages 等旧文档；
- 学校课程作业、毕业论文、研究笔记；
- 工作报告、方案、流程文档、教案、演示、作品集；
- GitHub / GitLab / 本地代码仓库；
- Figma、设计源文件、摄影 / 绘画 / 音视频工程；
- 相册和截图；
- 邮件、Slack、Discord 或其他聊天记录，在用户明确愿意纳入时；
- ChatGPT、Claude 等 AI 对话导出；
- 简历、个人主页、作品集页面；
- 用户本人对重要阶段、项目或作品的回忆。

不要把以上列表变成强制问卷。只需要找出用户最容易提供的几个入口。

## 2. 优先级：先吃现成的大块信息

优先处理满足以下条件的来源：

1. 已经存在，不需要用户重新手录；
2. 覆盖时间较长；
3. 原始信息较完整；
4. 能批量导出或访问；
5. 对未来 AI 理解用户或继续工作有明显价值。

例如：

- 十年阅读历史通常比临时整理十条“最喜欢的书”信息量更高；
- 一整个旧博客比让用户手动列兴趣标签更可靠；
- 一个作品文件夹比“我会设计”更能说明实际实践范围；
- 一份简历可以快速搭建工作时间骨架，但不能替代对具体能力边界的理解。

## 3. 发现以后先决定是否值得沉淀

Discovery 不是“发现什么就复制什么”。对每个来源选择最合适的保存方式。

### 全文 / 原始内容保存

适合：

- 用户自己的重要文本产出；
- 难以从外部重新取得、且长期价值高的材料；
- 原始措辞本身对未来理解非常重要的记录。

### Record / Pointer

适合：

- 大型代码仓库、设计工程、视频等已有自然 canonical 位置的成果；
- 可以稳定重新访问的外部平台记录；
- 原文件过大或格式不适合放进 Vault，但其存在、时间、位置和关键信息值得长期保留的材料。

### 不纳入 Vault

适合：

- 低信息量、重复、临时或无长期用途的痕迹；
- 仅因为“曾经存在”但未来几乎不会改变 AI 理解或工作方式的材料；
- 用户不希望长期保存的敏感内容。

“值得沉淀”不是“重要人生事件”的同义词。判断标准是：**未来 AI 是否可能因为保留这份材料而更准确地理解、检索或继续工作。**

## 4. 不同痕迹只能证明不同事情

处理每种来源前，先判断它的证据强度。

### 强痕迹

通常能直接证明某个事件或实际产出存在：

- 发布过的文章；
- 完整作品文件；
- Git 仓库；
- 提交记录；
- 工作交付物；
- 明确的完成 / 发布时间。

### 中等痕迹

通常能证明接触、参与或某种行为，但不能自动推出态度：

- 平台标记“读过 / 看过 / 玩过”；
- 评分；
- 收藏；
- 课程记录；
- 照片；
- 聊天记录。

### 弱痕迹

通常只能作为线索，不能直接形成强结论：

- Downloads 中出现一个 PDF；
- 浏览器历史；
- 文件名；
- 一张无上下文截图；
- 一次搜索记录。

弱痕迹可以帮助发现 corpus，但不能凭自己升级成兴趣、观点、能力或完成经历。

## 5. 先建立时间骨架

如果材料零散，先尝试恢复几个时间锚点：

- 学习阶段；
- 工作阶段；
- 长期居住 / 环境变化；
- 重要项目；
- 创作或研究阶段；
- 明显的平台 / 工具迁移。

时间骨架的作用是帮助解释材料，不是制造完整人生传记。

如果时间只能粗略恢复，保留范围，不要假装精确。

## 6. 用户记忆也是合法来源

如果用户几乎没有历史存档，不代表无法使用本 Skill。

可以让用户先提供一个粗略骨架，例如：

```text
大学阶段：主要学什么，做过什么重要项目
第一份工作：主要职责，留下了哪些材料
某段创作期：写过什么，资料现在在哪里
近几年：哪些方向持续存在，哪些只是短期项目
```

这些属于用户的当前回忆 / 自述，应和历史原始记录区分 provenance，但可以作为首轮建库的重要证据。

## 7. 发现而不侵入

不要默认把高隐私数据纳入 Vault。

邮件、聊天、私人照片、健康、财务、亲密关系等内容只在用户明确选择时处理，并优先让用户控制范围。

如果一个来源对当前目标没有明显价值，就不必为了“完整”强行导入。

## 8. Discovery 输出

完成盘点后，只需要形成一个简短的 source map，并标记建议保存方式：

```text
可用来源：
- 2016–2024 阅读平台导出 → 结构化导入
- 2019–2023 博客 → 全文保存
- 2021–现在 工作文档目录 → 先索引，再选重要成果
- 若干设计项目文件 → output record + 原路径
- 用户可补充大学阶段经历 → 访谈记录

暂不处理：私人聊天、照片
主要缺口：2017–2019 工作经历材料稀少
```

这个 map 用来指导首轮回填，不是长期用户画像。
