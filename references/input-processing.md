# Input Processing

输入是进入过用户注意、学习、消费或参考环境的外部信息。不同平台和文件只提供不同强度的 evidence，不能直接被 AI 解释成观点或稳定偏好。

## 1. 先区分用户原始信息和 AI enrichment

用户原始信息应忠实保留，例如：

- 评分；
- 日期；
- 原始短评；
- 用户自己写的标签；
- 阅读 / 观看 / 游玩方式；
- 当时留下的备注。

AI 可以另外补：

- canonical identity；
- 作者 / 主创；
- 出版 / 上映年份；
- 客观简介；
- 检索 facets；
- 去重和别名信息。

不要让 AI enrichment 覆盖原始用户记录。

## 2. 不同数字痕迹的证据边界

### 平台标记“读过 / 看过 / 玩过”

通常可以证明某种消费经历，但要保留平台语义。若平台字段含义不清，不擅自解释。

### 评分

可以保存为当时的明确评价信号，但一次高分不自动等于稳定偏好。

### 收藏 / 稍后读 / 浏览器书签

通常只证明保存、感兴趣或准备以后查看，不证明已经消费，也不证明赞同。

### 下载文件

通常只证明文件曾被保存。除非有更多 evidence，不要写成“用户读过”。

### 课程 / 书单 / 研究资料

可以证明某段学习或研究环境里接触过相关信息，但不自动证明全部掌握。

### 聊天 / AI 对话

可用于恢复当时正在思考的问题、用户明确自述和项目过程，但必须区分用户原话与 AI 生成内容。

## 3. 豆瓣式记录只是一个示例

一个结构化书影音平台可能提供：标题、评分、日期、短评、标签。

处理时：

```text
用户字段 → 原样保存
作品身份 → AI 核对
客观简介 → AI 补充
用户没有写的反应 → 不猜
```

同样的原则可以迁移到 Goodreads、Letterboxd、Steam、音乐平台或其他服务。

## 4. 主观原话优先保真

用户短评、标签、自由备注首先是历史 evidence，不是等待 AI “润色”的文本。

如果需要生成 summary，另存 AI summary，不要替换原话。

用户多年后重新解释一条旧记录时，也要和当时原评分开。

## 5. 批量输入不要逐条制造人格 insight

当导入几百条阅读、观看或收藏记录时，不要为每条生成“这说明用户……”式洞察。

正确做法是：

1. 先完成 canonical archive；
2. 保留时间和 provenance；
3. 再对整个 corpus 做 synthesis；
4. 在整体层面判断结构、阶段、稳定主题和边界。

## 6. 缺失信息不要补猜

典型错误包括：

- 没短评 → “用户没留下深刻印象”；
- 五星 → “这是用户的核心审美”；
- 收藏文章 → “用户赞同作者”；
- 下载论文 → “用户已经读过”；
- 某类内容最近很多 → “用户最近转向这个领域”。

这些都需要额外 evidence。

## 7. 输入处理输出

每批处理后应能回答：

- 哪些是用户原始数据；
- 哪些是 AI enrichment；
- 哪些字段仍未知；
- 这批数据只是在扩充 corpus，还是已经足以影响 corpus synthesis。

大多数批量输入首先只是 evidence 增长。
