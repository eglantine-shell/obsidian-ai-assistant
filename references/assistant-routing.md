# Assistant Routing

AI 不需要每次扫描整个 Vault。正确做法是先判断当前任务，再加载最小必要的工作规则和上下文。

## 1. 推荐读取顺序

```text
当前用户请求
→ global agent rules / work manual
→ 当前 project / domain 的操作协议
→ AI 导航
→ 最相关的 corpus synthesis 或 project record
→ 必要时 cross-corpus synthesis
→ 只有核实具体事实时才读原始 Sources / Outputs
```

规则和上下文是两类不同内容：先确保 AI 知道“怎样工作”，再读取完成当前任务所需的“关于用户 / 项目发生过什么”。

## 2. 先解决任务，再决定需要什么

有些任务需要大量历史背景，例如：

- 职业方向判断；
- 长期创作分析；
- 能力范围判断；
- 比较当前选择和过去实践。

有些任务主要需要工作手册和局部项目状态，例如：

- 继续一个有固定协作协议的长期项目；
- 按既定审稿 / 归档 / 发布流程处理新材料；
- 执行某个已有触发节点。

还有些普通事实问题可能既不需要用户模型，也不需要额外工作规则。

不要因为 Vault 里有很多个人资料或规则，就全部带进每个回答。

## 3. AI 导航应当是机器侧路由

AI-NAV 或等价文件可以记录：

- 能力问题先读哪里；
- 职业经历先读哪里；
- 某类创作先读哪个 synthesis；
- 某个 active project 从哪里继续；
- 当前任务应加载哪个 project / domain work manual；
- 哪些信息属于 Sources，只能作为 evidence；
- 哪些 output 是 AI-assisted；
- 哪些重要语义修改需要用户确认。

导航本身不应重复保存大量用户事实，也不应复制整份工作规则正文。

## 4. 工作规则按最小作用域加载

优先级通常是：

1. 当前用户明确指令；
2. 当前 task-local 规则；
3. 当前 project / domain 协议；
4. global agent rules。

更具体、更新的明确规则可以覆盖更一般的旧规则。

不要把一个项目里的习惯推断成全局偏好，也不要因为存在 global work manual 就忽略项目自己的协议。

## 5. 优先 synthesis，必要时再回 evidence

例如用户问：

> 我以前是不是长期喜欢某类小说？

先读阅读 corpus synthesis。

只有需要确认具体书目、年份或原评时，再下钻平台记录。

用户问：

> 我当年那篇文章到底怎么写的？

直接回到原始 output，而不是让 synthesis 代替原文。

## 6. Cross-corpus retrieval 是有条件的

只有问题本身需要多个领域共同解释时，才读取跨 corpus 材料。

例如：

- 判断长期能力时，需要把作品、项目和结果结合；
- 判断某个近期方向是否只是短期活动时，需要历史 corpus 校准；
- 判断某种实践是否跨场景持续存在。

不要因为“多读一些也没坏处”就加载所有 bridge。

## 7. 当前用户陈述优先

如果用户当前明确说：

> 我现在已经不这么想了。

旧 synthesis 不能用来覆盖当前声明。

如果用户当前明确说：

> 这类任务以后不要这样处理。

旧工作手册也不能用来覆盖这次纠正。

正确做法是：

- 当前任务按新信息执行；
- 如果这是长期变化，再走 maintenance / work-manual protocol；
- 旧信息在有历史价值时可以保留为过去状态，但不要让冲突规则同时保持 active。

## 8. 避免两种失败

### Amnesia

明明 Vault 已有长期资料和协作规则，却让用户反复重新解释。

### Overfitting

读了太多历史，把每个普通问题都解释成“因为你是某种人”，或者把所有旧规则机械套到当前任务。

一个好的 AI 助理需要同时避免这两种问题。

## 9. Task-specific working context

必要时，AI 可以临时组织一个小型工作上下文：

```text
当前任务：
当前适用规则：
相关稳定背景：
相关当前状态：
相关历史变化：
重要边界：
仍不确定：
```

这个 working context 默认是临时的，不需要自动写回 Vault。

只有任务中出现真正的新 evidence、长期变化或可复用工作规则，才进入正式维护流程。

## 10. AI 导航维护原则

当新增 corpus、项目或工作协议时，只有未来检索路径真的改变，才更新 AI 导航。

不要把 AI-NAV 写成一个无限增长的用户百科或规则全文。它应该始终主要回答：**去哪里找。**

工作规则的创建和作用域见 `work-manual.md`。
