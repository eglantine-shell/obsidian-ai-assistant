# Assistant Routing

AI 不需要每次扫描整个 Vault。正确做法是先判断当前任务，再加载最小必要上下文。

## 1. 推荐读取顺序

```text
当前用户请求
→ AI 导航 / Agent rules
→ 最相关的 corpus synthesis 或 project record
→ 必要时 cross-corpus synthesis
→ 只有核实具体事实时才读原始 Sources / Outputs
```

## 2. 先解决任务，再决定是否需要个人上下文

有些任务需要大量历史背景，例如：

- 职业方向判断；
- 长期创作分析；
- 能力范围判断；
- 继续一个长期项目；
- 比较当前选择和过去实践。

有些任务只需要局部上下文，例如：

- 修改某篇文章；
- 继续某个代码项目；
- 查某段旧记录。

还有些普通事实问题可能完全不需要用户模型。

不要因为 Vault 里有很多个人资料，就把它们全部带进每个回答。

## 3. AI 导航应当是机器侧路由

AI-NAV 或等价文件可以记录：

- 能力问题先读哪里；
- 职业经历先读哪里；
- 某类创作先读哪个 synthesis；
- 某个 active project 从哪里继续；
- 哪些信息属于 Sources，只能作为 evidence；
- 哪些 output 是 AI-assisted；
- 哪些重要语义修改需要用户确认。

导航本身不应重复保存大量用户事实。

## 4. 优先 synthesis，必要时再回 evidence

例如用户问：

> 我以前是不是长期喜欢某类小说？

先读阅读 corpus synthesis。

只有需要确认具体书目、年份或原评时，再下钻平台记录。

用户问：

> 我当年那篇文章到底怎么写的？

直接回到原始 output，而不是让 synthesis 代替原文。

## 5. Cross-corpus retrieval 是有条件的

只有问题本身需要多个领域共同解释时，才读取跨 corpus 材料。

例如：

- 判断长期能力时，需要把作品、项目和结果结合；
- 判断某个近期方向是否只是短期活动时，需要历史 corpus 校准；
- 判断某种实践是否跨场景持续存在。

不要因为“多读一些也没坏处”就加载所有 bridge。

## 6. 当前用户陈述优先

如果用户当前明确说：

> 我现在已经不这么想了。

旧 synthesis 不能用来覆盖当前声明。

正确做法是：

- 当前任务按新信息理解；
- 如果这是长期变化，再走 maintenance protocol；
- 旧信息可以保留为历史状态。

## 7. 避免两种失败

### Amnesia

明明 Vault 已有长期资料，却让用户反复重新解释。

### Overfitting

读了太多历史，把每个普通问题都解释成“因为你是某种人”。

一个好的 AI 助理需要同时避免这两种问题。

## 8. Task-specific working context

必要时，AI 可以临时组织一个小型工作上下文：

```text
当前任务：
相关稳定背景：
相关当前状态：
相关历史变化：
重要边界：
仍不确定：
```

这个 working context 默认是临时的，不需要自动写回 Vault。

只有任务中出现真正的新 evidence 或长期变化，才进入正式维护流程。

## 9. AI 导航维护原则

当新增 corpus 或项目时，只有未来检索路径真的改变，才更新 AI 导航。

不要把 AI-NAV 写成一个无限增长的用户百科。它应该始终主要回答：**去哪里找。**
